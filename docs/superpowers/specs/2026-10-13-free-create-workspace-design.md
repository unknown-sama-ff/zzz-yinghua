# 自由创作工作台设计提案

日期：2026-10-13
状态：自由创作工作台 v1 已实现；文末包含本地模拟演示与真实效果限制。
已确认场景：角色三视图配多个目标画面逐图替换；固定场景（如婚礼背景）配多个角色分别生成；多会话同时生图；失败原位重试。

## 目标与方案选择

让失败请求可以直接重试，让用户在一个会话生成时继续新建或切换其它会话，并让三视图无需为每张目标图重复上传。

- **极简按钮修补**：增加重试、放开新建，改动小，但主体图、目标图和批量任务仍混在聊天输入中，难以解决逐图角色替换。
- **统一工作台（推荐）**：沿用自由创作入口，支持展开；用两种模式组织普通创作与批量替换，共用会话、任务状态和参考图操作。
- **项目素材库**：跨页面保存角色、素材与作品，适合长期项目，但需要持久存储、素材管理和更多交互，本轮排除。

## 界面与会话

保持当前自由创作入口，打开后可展开为较宽的工作台。桌面端显示会话列表、创作内容和输入区；窄屏显示会话切换条与当前内容，保证生成、重试和目标图状态可见。

顶部提供“新建”“沿用素材新建”和会话切换，输入区加入可折叠的“批量复用”：

- **普通自由创作**：保留文字生图、参考图生图、成图继续修改、比例和数量设置。发送与重试时使用明确的当轮输入；当前上下文可查看、切换或清除。
- **批量复用**：展开后选择“固定角色换画面”或“固定背景换角色”，提供一个共用图片槽位和逐项素材区。卡片显示原图、结果、任务状态、错误以及重试入口。用户填写一份公共补充说明，点击批量生成，每项独立得到结果；收起后回到普通创作。

“新建”建立空会话；“复制当前会话”复制当前模式、输入素材、说明与设置，作为独立草稿，不复制正在运行的任务。会话显示排队、生成中、完成、失败数量；生成中可以新建和切换，收起窗口不终止任务。切换模式保留各模式草稿，已提交任务继续使用原快照。

会话、三视图、参考图、结果和凭据仅保留在当前页面内存中；刷新页面后清空。三视图在同一会话的各批次中持续复用，复制会话可带入它，本轮不增加跨刷新素材库。

普通文字创作不要求上传三视图；普通模式可移除主体图，批量角色替换必须有三视图与至少一张目标图。新会话的精细度默认沿用现有全局设置，已提交任务保存发送时的实际精细度，不受之后设置变化影响。

## 批量角色替换

每批最多 16 张目标图。每张目标图默认只包含一个需要替换的人物；多个角色的精确定位或局部蒙版不在本轮范围。可增删目标图，单张生成或全部排队；已提交任务的图片与设置不受后续草稿修改影响。

每个子任务独立构造请求，固定 `n=1`：

1. 目标图作为主图，保留其动作、机位、构图和背景。
2. 角色三视图作为第一张参考图，提供脸、发型、体型与角色身份依据。
3. 其它参考图若用户添加，则按界面显示顺序追加。

“固定背景换角色”反向复用：每个子任务均以同一背景图为主图，当前项的角色三视图作为参考图。保持背景、机位、场景布局，将角色放入用户指定位置；每张角色图分别生成一幅画面。同一婚礼画面中同时加入多个人物则使用普通创作，以背景为主图并附多张角色图，在提示词中说明左右位置与动作，不把逐项生成误认为多人合成。实际身份保真与布局效果需要真实模型验证。

默认“保留角色原服装”，服装以三视图为准；可选“沿用目标图服装”，仅改变服装依据，角色身份仍以三视图为准。界面将这两项解释为用户选择，提示词明确输入图职责。公共补充说明应用到每个子任务。前一张替换结果不会成为下一张的上下文，避免角色和构图逐步漂移。

“批次最多 16 张目标图”和“单个请求输入图片上限”分别校验：前者控制任务数量，后者计算主图、三视图及全部附加参考图的总数。沿用当前自由创作请求的多图策略与服务端上限（当前为 17 张总输入）；未知模型不因本仓库其它模块的保守能力表而被前端阻断。上游仍可能拒绝实际不支持的多图请求，届时保留任务并给出错误及修改入口。

## 原位重试与恢复草稿

提交前建立不可变任务快照，包含提示词、所有输入图及顺序、上下文、模式、服装选择、数量、比例、质量和提供方配置。凭据只存在内存中的请求配置，不写入本地存储、日志、设计导出或错误详情。

失败任务提供：

- **重试**：使用原任务快照重新排队；成功卡片与其它任务不受影响。每次尝试有新的 attempt token 和幂等键；同一次网络发送的重复提交共用其幂等键。失败结果的旧幂等缓存不会让新尝试立即重复失败。
- **恢复为草稿**：恢复原提示词、图片和设置，用户可修改后重新提交。若当前输入区已有草稿，恢复到新会话，避免覆盖现有内容。

任务记录逻辑任务 ID、会话 ID、批次/目标图 ID 和当前 attempt token。迟到响应只有匹配当前尝试时才回写；每次提交、重试按钮连续点击均只产生一个有效尝试。异步上传开始时固定目标会话与素材区域，读取完成后仍写入原会话，切换会话不会把图片加错位置。

超时、断网或轮询失联时显示“结果尚未确认”，不自动重新生图。若已获得服务端 taskId，则提供继续查询；用户明确再次生成时提示原请求仍可能完成、再次请求可能消耗额度，并使用新的尝试与幂等键。已确认失败的 400 可以原位重试，但持续失败时应恢复草稿调整输入；重试不承诺解决上游参数或模型限制。

用户可展开错误详情。代理清洗上游消息，移除鉴权信息、内部地址和原始长响应，保留可用的状态码、错误类别与上游请求 ID；没有上游请求 ID 时展示本次应用请求 ID，不伪造诊断信息。

## 并发、暂停与预算

整个自由创作工作台共用一个最多 **2 个进行中请求** 的调度器。普通会话每次最多一个任务进行中，其它请求排队；批量子任务独立排队，可以同时占用两个公共槽。会话按轮转顺序取队列任务，避免一个大批次长期挡住另一个会话。排队顺序与结果归属由任务 ID 决定，完成顺序不改变目标图排列。

暂停批次只阻止未出队任务，已发送请求继续等待并回写。普通上游 429 暂停同一凭据来源的未出队任务，保留“继续任务”入口；每日免费额度耗尽或鉴权失败则暂停该凭据来源，用户修复设置、切换凭据或额度恢复后手动继续。更新凭据必须显式应用到待继续的任务，图片与生成参数快照保持不变。

复用现有 `/api/generate` 和任务查询接口，客户端组织队列与请求。服务端已有免费额度在调用上游前扣除、失败后不退款的行为，本轮保持并在批量启动与失败重试处提示；不将前端暂停说成服务器取消或额度退款。并发为前端调度限制，服务端继续执行现有限流及预算检查。

## 实现边界与必要兼容修改

主要改动位于自由创作 UI、会话 Store、请求构造与共享 API 客户端。需要独立的任务状态与调度层，替代当前全局 `isGenerating`；现有消息、下载、图库保存与放大预览继续复用。

并发开启前必须修复 JSON Worker 的响应关联：每次解析携带唯一 requestId，Worker 回复同一 requestId，客户端仅处理匹配的响应。成功、失败、超时均移除对应监听器与计时器，迟到回复不影响其它请求。API 错误结构增加可选状态码和请求 ID，保证串行调用也兼容。结果只能更新发起请求的会话、消息或目标卡片，不能覆盖用户之后主动选择的普通创作上下文。

服务端幂等记录在请求进行中保持有效，结束后再开始五分钟缓存期，避免较慢请求尚未完成就失去去重能力。限流错误增加可选原因字段，区分请求频率、免费额度与上游限流；有明确等待时间时返回该时间。客户端按原因暂停队列，旧错误结构仍可显示并手动继续。

本轮排除跨刷新持久保存、项目素材库、多人物定位、蒙版编辑、自动无限重试与服务端取消；可点击草图展示操作与状态，用于评审，不调用真实生图 API。

## 验收

1. 上游 400 后原位重试，无需重传参考图或重写提示词；原图顺序、上下文、数量、比例与质量保持一致，恢复草稿不覆盖已有输入。
2. A 会话生成中可新建、复制并提交 B；最多两个请求进行中，完成或失败回到各自会话，收起后继续。
3. 一份三视图配三张目标图生成三个独立结果，各请求均是目标主图加同一三视图参考、`n=1`，不串用前一个结果；两个服装选项按各自规则构造提示词。
4. 单个普通会话重复点击、同一任务连续重试只产生一个有效尝试；过期 attempt 的迟到响应不覆盖新状态，并且新尝试使用新幂等键。
5. 上传读取中切换会话，图片仍归属原会话；队列中的素材修改不改变已提交快照，复制会话后草稿可独立修改。
6. 批次目标数量与单请求总输入图数量分别校验；未知模型保留现有自由创作多图策略，实际上游拒绝时保留可操作的错误任务。
7. 限流、每日额度或鉴权失败暂停对应未出队任务；已发送任务正常收尾，修复后手动继续。结果不明时不自动再生成，凭据不出现在持久存储或错误详情。
8. 两个并发请求的 JSON 响应以相反顺序到达、其中一个 Worker 解析失败或超时时，其它请求结果仍正确；监听器和计时器均清理，状态码/请求 ID 可用于排查。
