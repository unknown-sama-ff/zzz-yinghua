# 一键修腿

影画动作底稿和零命、三命、六命结果增加“一键修腿”入口，复用现有连续图片编辑工作区。针对第三条腿、多余小腿分支及腿部错接，用户一次点击提交一次图片编辑；结果先成为可对比的编辑版本，点击“替换动作底稿”或“替换影画原图”后才写回对应图片。

## 修复规则与边界

- 先沿髋、大腿、膝、小腿、踝、脚确认归属，优先保留结构完整的两条连接；完整程度相近时优先保留画面上方、髋膝连接清楚的腿，同时保留另一条正确的前景腿。
- 只有确认存在多余分支时才删除分支及其鞋袜并恢复背景；没有多余腿时仅整理错位关节和轮廓。不会固定删除左下方的腿，也不强行补出遮挡或出框的部位。
- 保留角色身份、衣装、原镜头、透视、裁切、主体动作、文字与其他区域。编辑窗口内可从任一选中版本继续修复，精确模式仍要求当前蒙版。
- 使用现有 gpt-image 编辑设置与通道，不额外调用识图模型。每次主动点击仅提交一次编辑，拒绝后保留原图、提示词及上游诊断，由用户决定是否重试。
- 请求期间防止重复提交；过期图片在请求前拦截，过期会话的响应不能写入或解锁新会话。替换时再次校验来源，六命阴阳面分别写回。
- 保留两阶段默认模式与现有审核提示。本功能面向已经生成的图片，不解决第一阶段的上游审核拒绝。

## 验证

- `npm test`：141 项通过，包含重复点击、旧会话响应、审核拒绝、过期来源、精确模式蒙版的回归测试。
- `npm run lint`、`npm run build`：通过。
- `tests/browser/leg-repair-smoke.mjs`：5 项通过，覆盖单次请求、原图保留、版本对比与继续修复、显式替换、六命阴面归属、审核拒绝与 390px 布局。
- 既有两阶段、工作室、查看器与图库浏览器流程通过。
- 截图及结果：`tests/browser/artifacts/leg-repair/`。

模型接口均被测试拦截，测试素材为合成色块，未上传用户角色图、未消耗真实生图额度。上述验证证明网站交互与请求规则生效，不证明真实模型一定修复成功或通过审核。
