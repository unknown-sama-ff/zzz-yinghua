# 影画错误来源修正

用户确认旧方法与第一阶段使用同一角色图、模型和通道，并要求保留镜头与动作，只修正诊断信息。

## 已确认的问题

- 原来的“模型内容审核未通过……使用完整衣装……”为应用生成的中文提示，不是服务方逐字原文。`sexual` 从上游审核分类提取，原始消息没有传至前端。
- 同步返回丢失了原始消息；异步任务还把具体错误代码统一改成了 `UPSTREAM_ERROR`。

## 修正

- 将应用提示与 `upstreamError` 分开。后者保留服务方消息、实际 HTTP 状态、服务方代码/类型、审核类别及可用的服务方请求编号。
- 消息仅作凭证/图片数据脱敏和长度限制；页面明确标识这些处理，不翻译、不用建议文案替代原文。
- 同步请求、异步任务、API 客户端和影画状态都透传该结构。新一次生成清除旧错误证据。
- 没有原文的旧响应明确显示“应用提示（非上游原文）”，不伪造或还原旧记录。

## 生成差异与结论边界

代码中的第一阶段请求与直接生成存在差异：正常明暗全彩图与剪影的输出目标不同；第一阶段没有三张零命风格样张；GPT 输入处理长边分别为 1536 与直接模式的 1024。

这些是代码可观察差异，不是用户真实请求的完整抓包，也不能证明某一差异造成审核拒绝。本次不更改提示词、镜头、动作、模型、参考图组合或分辨率，不发送真实模型 A/B 请求，不在拒绝后自动切换参数或生成方式。

## 验证

新增 7 项测试覆盖原文分离、凭证/图片脱敏、同步与异步错误透传、API 客户端 HTTP/JSON/轮询错误路径。项目共 132 项测试通过；浏览器流程 9 项通过，包含旧响应诚实标注和原文逐字显示。类型检查、正式构建通过。

真实模型仍可能拒绝第一阶段；此修正解决信息失真，不代表审核原因已确定或审核通过率已改善。所有回归响应均为本地模拟，未产生付费生图调用。
